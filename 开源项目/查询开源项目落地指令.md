每周分析上一个自然周 GitHub 上的开源商业化 AI Agent 项目。

目标：
找出净新增 Star 最高、已经解决明确商业业务问题的项目，最多输出 10 个。宁缺毋滥，不得使用通用 Agent、框架、Memory、Skill、MCP、模型、教程或开发基础设施凑数。

统计周期：
按 Asia/Shanghai 时区计算上周一 00:00 至上周日 23:59。

数据要求：
1. 保存每次运行时的仓库 Star 快照。
2. 使用期末 Star 减去期初 Star计算自然周净增量。
3. 不得把当前累计 Star、GitHub Trending 顺序或估算值冒充周增量。
4. 缺少基线数据时标记“无法验证”，不得填写估算数字。
5. 若合格项目少于 10 个，明确报告实际数量。

纳入条件：
- 有明确的企业或职业用户；
- 解决销售、客服、招聘、营销、财务、法务、安全、医疗、电商、研究或运营等具体业务问题；
- 能自主完成多步骤业务流程；
- 具备可运行的 UI、服务、API 或完整工作流；
- 核心代码开源；
- 有付费版、企业版、托管服务、商业支持或清晰商业模式等商业化信号。

排除：
- 通用个人 Agent；
- 编程 Agent；
- Agent 框架、SDK、Memory、RAG、数据库；
- MCP、沙箱、浏览器和工具调用基础设施；
- Skill、Prompt、角色模板；
- 模型、训练或推理项目；
- 教程、Awesome List 和演示仓库；
- 只有聊天能力、没有业务闭环的项目。

排名：
先按资格过滤，再按自然周净新增 Star 降序排列。商业成熟度评分仅作为辅助信息，不改变 Star 排名。

输出：
生成中文表格，包含排名、项目、期初 Star、期末 Star、净增 Star、业务场景、目标客户、交付结果、商业化信号、许可证和成熟度评分。
每个结论必须附 GitHub 或官方产品页面链接。
最后列出：
1. 最值得试用的三个项目；
2. 新出现的商业 Agent 赛道；
3. 被排除的高 Star 项目及具体原因。
