# Aix-DB Agent 项目系统分析报告

## 1. 项目定位

### 1.1 这个项目是做什么的？

Aix-DB 是一个基于大语言模型和 RAG 技术的**智能数据分析系统**，核心定位是实现**对话式数据分析（ChatBI）**。它让用户用自然语言提问，系统自动完成 SQL 生成、数据查询和可视化呈现。

### 1.2 它解决了什么业务问题？

在 Aix-DB 出现之前，企业的数据分析流程通常是：业务人员提需求 → 数据分析师写 SQL → 分析师跑数 → 返回结果。这个流程存在三大痛点：

| 痛点           | 说明                                                         |
| :------------- | :----------------------------------------------------------- |
| **沟通成本高** | 业务人员不懂 SQL，分析师不懂业务，来回确认需求可能折腾几天   |
| **技术门槛高** | 即便业务人员学了 SQL，面对复杂表结构和业务逻辑仍难写出正确查询 |
| **可视化缺失** | 拿到原始数据后，如何做成图表展示是另一个问题                 |

Aix-DB 通过大语言模型的理解能力和 RAG 检索能力，让业务人员能用自然语言直接查询数据，并自动生成可视化图表。

### 1.3 目标用户是谁？

- **不懂技术的业务人员**：产品、运营、市场等岗位，需要快速获取数据洞察
- **希望提升效率的数据分析师**：用 AI 辅助完成重复性的 SQL 编写工作
- **开发者与研究人员**：需要快速部署 LLM 应用框架

### 1.4 它属于哪一类 Agent？

**数据分析 Agent（ChatBI Agent）** 。

具体来说，它是一个**多 Agent 协作系统**，包含多个专门化 Agent 协同工作：

- **SQL Agent**：专门负责 SQL 生成和优化
- **RAG Agent**：负责知识检索
- **Chart Agent**：负责选择合适的可视化方案
- **MCP Skills**：支持扩展更多自定义技能

### 1.5 为什么这个项目需要用 Agent，而不是普通应用？

| 原因                 | 说明                                                         |
| :------------------- | :----------------------------------------------------------- |
| **自然语言理解复杂** | 需要 LLM 解析意图、抽取实体、理解业务上下文，不是简单的关键词匹配 |
| **任务需要拆解**     | 一个自然语言问题需要拆解为意图理解、schema 检索、SQL 生成、结果解释等多个子任务 |
| **动态决策**         | 系统需要根据问题类型动态决定调用哪些工具、检索哪些知识       |
| **多轮对话**         | 支持“越问越准”的迭代式分析，需要记忆和上下文管理             |
| **多智能体协作**     | 不同 Agent 负责不同任务，可独立优化和扩展                    |

## 2. 业务流程

### 2.1 用户输入什么？

用户以**自然语言**提出数据查询问题，例如“去年华北区的销售额是多少？”。

### 2.2 系统输出什么？

系统输出包含两部分：

1. **数据结果**：从数据库查询到的结构化数据
2. **可视化图表**：自动生成的 ECharts/AntV 图表

### 2.3 完整业务流程

| 步骤 | 做了什么                                                     | 目的                     | 涉及模块       |
| :--- | :----------------------------------------------------------- | :----------------------- | :------------- |
| 1    | 用户以自然语言输入数据查询问题                               | 提出分析需求             | 前端（Vue 3）  |
| 2    | LLM 解析问题意图，抽取关键实体和查询条件                     | 理解用户想要什么         | LLM 服务       |
| 3    | Embedding + BM25 混合检索，结合 Neo4j 图谱获取相关表结构和业务知识 | 找到正确的数据表和字段   | RAG 检索引擎   |
| 4    | Text2SQL 引擎生成 SQL 语句，进行语法校验和优化               | 将自然语言转为可执行查询 | Text2SQL Agent |
| 5    | 在目标数据源执行 SQL                                         | 获取真实数据             | 数据库层       |
| 6    | 自动生成 ECharts/AntV 图表                                   | 直观呈现分析结果         | 可视化组件     |

### 2.4 具体例子

**用户提问**：“去年华北区的销售额是多少？”

1. **意图理解**：LLM 解析出关键实体——时间（去年）、地域（华北区）、指标（销售额）
2. **RAG 检索**：从向量数据库和 Neo4j 图谱中检索“销售额”对应的表名、字段名，以及“华北区”在数据库中的映射关系
3. **SQL 生成**：Text2SQL 引擎生成类似 `SELECT SUM(amount) FROM orders WHERE region='华北' AND year=2025` 的 SQL
4. **数据库执行**：在 MySQL/PostgreSQL 等数据源执行 SQL
5. **可视化展示**：自动生成柱状图或趋势图展示结果

## 4. Agent 核心设计

### 4.1 Agent 的角色是什么？

Aix-DB 采用**多 Agent 协作架构**，每个 Agent 有专门职责：

| Agent              | 职责                                     |
| :----------------- | :--------------------------------------- |
| **意图理解 Agent** | 解析用户自然语言，抽取关键实体和查询条件 |
| **RAG Agent**      | 负责知识检索，获取表结构和业务知识       |
| **SQL Agent**      | 专门负责 SQL 生成和优化                  |
| **Chart Agent**    | 负责选择合适的可视化方案                 |
| **深度问数 Agent** | 支持复杂多轮分析                         |

### 4.2 Agent 如何理解用户任务？

通过 **LLM 意图理解**：大模型解析问题意图，抽取关键实体和查询条件。对于复杂问题，会触发深度问数模式进行更细致的任务拆解。

### 4.3 Agent 是否会进行任务拆解或规划？

**会**。项目采用了 MCP Skills 多智能体协作架构，支持复杂的任务分解和执行。具体体现在：

- 通过 **LangGraph** 构建状态图，实现多步骤任务编排
- **DeepAgent** 专门处理需要多轮推理的复杂查询
- 不同 Agent 分工协作，每个负责特定环节

### 4.4 Agent 如何决定是否调用工具？

Agent 通过 **LangChain/LangGraph 的 ReAct 模式**进行决策：

1. LLM 分析当前状态和用户问题
2. 判断是否需要调用工具（如 SQL 执行、RAG 检索）
3. 根据工具返回结果决定下一步行动
4. 循环直到生成最终答案

项目中的 `common_react_agent.py` 和 `enhanced_common_agent.py` 实现了这一模式。

### 4.5 项目中有哪些 Tools？

| 工具            | 位置                 | 功能                       |
| :-------------- | :------------------- | :------------------------- |
| SQL 执行工具    | `text2sql/database/` | 在目标数据库执行 SQL       |
| RAG 检索工具    | `text2sql/rag/`      | 检索表结构和业务知识       |
| 图表生成工具    | `text2sql/chart/`    | 自动生成 ECharts/AntV 图表 |
| 深度分析工具    | `deepagent/tools/`   | 复杂数据分析               |
| Schema 探索工具 | `deepagent/tools/`   | 发现和理解数据库架构       |

### 4.6 是否使用 RAG、MCP 或 Skills？

| 技术       | 使用情况                                     |
| :--------- | :------------------------------------------- |
| **RAG**    | ✅ Embedding + BM25 混合检索 + Neo4j 图谱检索 |
| **MCP**    | ✅ MCP Skills 多智能体协作架构                |
| **Skills** | ✅ Skill 模式，支持扩展自定义技能             |

### 4.7 Agent 如何生成最终结果？

text

```
用户问题 → 意图理解 → RAG检索 → SQL生成 → 数据库执行 → 数据分析 → 图表生成 → 返回结果
```



最终输出包含：**数据表格 + 可视化图表 + LLM 生成的业务洞察**。

### 4.8 是否支持多轮对话、记忆或上下文管理？

**支持**。项目包含：

- `agent/context/` 目录负责上下文管理
- `agent/mcp/query_qa_history.py` 负责问答历史记录
- 产品特点中提到“越问越准”，支持多轮迭代式分析

## 5. 工程化与可落地性

| 维度                | 当前实现                                               | 不足                                                    | 改进建议                                                     |
| :------------------ | :----------------------------------------------------- | :------------------------------------------------------ | :----------------------------------------------------------- |
| **异常处理**        | Text2SQL 引擎包含语法校验和优化；Docker 部署有健康检查 | 未见详细的异常重试和降级机制                            | 增加 SQL 执行超时重试、LLM 调用降级方案                      |
| **日志和监控**      | 集成 LangFuse Tracing；日志挂载到 `./volume/logs/`     | 缺乏业务指标监控和告警                                  | 接入 Prometheus/Grafana，增加业务指标（查询成功率、响应时间） |
| **权限控制**        | JWT 认证；有 `permission` 模块                         | 权限粒度较粗，缺少行级/列级数据权限                     | 集成 RBAC，实现数据源级别的权限隔离                          |
| **工具调用安全**    | SQL 生成后经过语法校验和优化                           | 存在安全漏洞 CVE-2026-4530；缺少 SQL 注入防护和操作审计 | 使用参数化查询、增加 SQL 白名单、记录所有查询审计日志        |
| **RAG 没命中处理**  | 混合检索（Embedding + BM25 + Neo4j）提高召回率         | 未见明确的“未命中”降级策略                              | 增加提示用户补充信息、返回相似问题建议、或回退到通用问答     |
| **扩展新工具/场景** | Skill 模式支持自定义扩展；MCP 支持多智能体协作         | 扩展文档不够详细                                        | 完善 Skill 开发文档和示例                                    |
| **企业级补充能力**  | 支持 8+ 种数据库；Docker 一键部署                      | 缺少 SSO、审计日志、数据脱敏、SLA 保障                  | 集成 OIDC/OAuth2、增加操作审计、支持数据脱敏、提供性能压测报告 |

**安全提醒**：项目存在已披露的 CVE-2026-4530 安全漏洞，影响 `terminology_retriever.py` 文件，企业部署前需评估和修复。

## 6. 总结与学习价值

### 6.1 核心亮点

1. **完整的多 Agent 协作架构**：基于 LangGraph + MCP 构建，不是简单的单 Agent 调用
2. **混合 RAG 检索**：Embedding + BM25 + Neo4j 图谱三重检索，提高 Text2SQL 准确率
3. **端到端的 ChatBI 方案**：从自然语言到可视化图表，开箱即用
4. **广泛的数据库支持**：8+ 种数据库类型，包括关系型、向量、图数据库
5. **Skill 可扩展模式**：支持用户自定义技能，灵活适配业务场景

### 6.2 不足

1. **安全漏洞**：存在已披露的 CVE 漏洞
2. **缺少企业级特性**：SSO、审计日志、数据脱敏等
3. **RAG 降级策略不明确**：检索未命中时缺少清晰的兜底方案
4. **License 不清晰**：Gitee 上标注“未声明开源许可证”

### 6.3 值得学习的设计

1. **分层架构**：前端 → API 网关 → 智能服务 → 数据存储，职责清晰
2. **多 Agent 分工**：SQL Agent、RAG Agent、Chart Agent 各司其职，可独立优化
3. **混合检索策略**：结合向量检索、BM25 和知识图谱，提升召回质量
4. **LangGraph 状态管理**：用状态图管理多步骤 Agent 流程，便于调试和扩展

### 6.4 不适合直接照搬的设计

1. **MCP 多智能体架构**：对简单场景可能过度设计，增加系统复杂度
2. **全量 Docker 部署**：包含 PostgreSQL、Neo4j、MinIO 等多个组件，资源消耗大
3. **Sanic 框架**：相对小众，企业可能更熟悉 FastAPI 或 Django

### 6.5 二次开发优先改进方向

1. **修复 CVE-2026-4530 安全漏洞**
2. **完善 RAG 降级策略**：检索未命中时提供清晰反馈
3. **增加企业级认证**：集成 OIDC/OAuth2 SSO
4. **增强权限管理**：实现数据源级别和行级权限控制
5. **补充单元测试和集成测试**：提高代码质量和可维护性
6. **完善 Skill 开发文档**：降低二次开发门槛

### 6.6 面试表达参考

> **项目背景**：Aix-DB 是一个基于大语言模型和 RAG 技术的开源智能数据分析系统，核心定位是实现对话式数据分析（ChatBI），解决传统数据分析中业务人员与数据之间的“最后一公里”问题。
>
> **技术架构**：项目采用四层架构——Vue 3 + TypeScript 前端层、Sanic API 网关层、基于 LangChain/LangGraph 的智能服务层、以及支持 PostgreSQL/Neo4j/向量数据库的多模数据存储层。
>
> **Agent 工作流**：用户输入自然语言问题后，系统经过 LLM 意图理解 → RAG 混合检索（Embedding + BM25 + Neo4j 图谱）→ Text2SQL 生成 → 数据库执行 → 自动图表生成，最终返回数据洞察。
